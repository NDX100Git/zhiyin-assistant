# 协作者上手 · 真机调试与多人协作

> 这份文档只解决两件事：**第二个人怎么接进来**、**怎么用 USB 在真机上调试**。
>
> 装环境、启动项目的基础流程看 `HANDOFF.md`；本文不重复。
> 注意：`HANDOFF.md` 里「App 端用 `plus.io.chooseFile`」那段已经过时，
> 现在实际用的是系统 `ACTION_GET_CONTENT` 选择器，以本文和代码为准。

## 1. 拿到仓库权限

仓库是 https://github.com/NDX100Git/zhiyin-assistant，默认只有 owner 能推。

**owner 要做**：GitHub 仓库 → Settings → Collaborators → Add people → 输入对方 GitHub 用户名 → 对方在邮件或 GitHub 通知里点接受。

**验证**：对方 `git clone` 后随便 `git commit` 一次再 `git push`，能推上去就算通了。

---

## 2. 克隆与分支

```bash
git clone https://github.com/NDX100Git/zhiyin-assistant.git
cd zhiyin-assistant
```

**分支建议**（两人协作，避免互相踩）：

| 场景 | 做法 |
|---|---|
| 改一个明确的 bug / 加一个小功能 | 直接改 `main`，push 前先 `git pull --rebase` |
| 改动跨多个文件、要几天 | 开分支 `feat/xxx`，改完提 PR 让 owner 看 |

每天开工前、每次 push 前都执行一次：

```bash
git pull --rebase
```

冲突了不要慌，`git status` 看哪些文件冲突，手工改完 `git add <文件>` 再 `git rebase --continue`。

## 3. 装环境（Windows）

| 组件 | 版本 | 说明 |
|---|---|---|
| Node.js | 18+ | 跑 uni-app 构建 |
| Python | 3.12+ | 后端，**不要用 3.11**，依赖装不上 |
| MySQL | 8.x | 数据库 |
| 对象存储 | — | 我们本机用的是 **moto**（Python 写的 S3 模拟器），比装 MinIO 省事 |
| LibreOffice | 7.x+ | 文档转 PDF、数页数，必须装 |
| HBuilderX | 4.x | 真机运行、云打包 |

**LibreOffice 装完记下 `soffice.exe` 的完整路径**，比如：

```
C:\Program Files\LibreOffice\program\soffice.exe
```

后面要写进 `.env` 的 `SOFFICE_PATH`。

## 4. 本地配置（三份文件，都不入库）

仓库里只有 `.env.example`，真实的 `.env` 各人本地生成，**不要提交**（`.gitignore` 已经挡住 `.env` 和 `.env.*`）。

### 4.1 后端 `backend/.env`

```bash
cd backend
copy .env.example .env
```

然后改这几项，其余保持默认：

```ini
# 数据库口令，自己定
DB_PASSWORD=你的口令

# 对象存储：用 moto 就跑在 9001，注意不用 9000
MINIO_ENDPOINT=127.0.0.1:9001
MINIO_ACCESS_KEY=minioadmin
MINIO_SECRET_KEY=minioadmin

# LibreOffice 实际安装路径（Windows 用反斜杠，不用引号）
SOFFICE_PATH=C:\Program Files\LibreOffice\program\soffice.exe
```

> **为什么用 9001 不用 9000**：9000 经常被别的程序占着，绑定会失败并报
> 「以一种访问权限不允许的方式做了一个访问套接字的尝试」。换端口最省事。

### 4.2 学生端 `student-app/.env.development.local`

```ini
VITE_API_BASE_URL=http://127.0.0.1:8010
VITE_POLL_INTERVAL=30000
```

> **为什么是 127.0.0.1 而不是电脑 IP**：走 USB 端口转发（见第 6 节），
> 手机上的 127.0.0.1 会被转发到电脑，不依赖 WiFi，电脑换网络也不用改。

### 4.3 学生端 `student-app/.env.production.local`

调试期可以同上。**但出正式 APK 前必须改成电脑局域网 IP**（如 `http://192.168.137.1:8000`），
否则装到手机上 127.0.0.1 指向手机自己，连不上后端。

## 5. 启动（四条命令，顺序别乱）

### 5.1 数据库

用免安装版（见 `HANDOFF.md` 第 3 步），或 Docker：

```bash
docker run -d --name zhiyin-mysql -p 3306:3306 \
  -e MYSQL_ROOT_PASSWORD=你的口令 -e MYSQL_DATABASE=zhiyin mysql:8
```

### 5.2 对象存储（moto）

```bash
cd backend
.venv\Scripts\python.exe -m moto.server -H 127.0.0.1 -p 9001
```

### 5.3 后端

```bash
cd backend
.venv\Scripts\python.exe -m uvicorn app.main:app --host 0.0.0.0 --port 8010
```

**端口用 8010，别用 8000**：HBuilderX 跑真机调试时会用 `httpServer.js` 占住 8000，
后端起不来，或者起了但手机请求打到 HBuilderX 上返回 404。

验证：

```bash
curl http://127.0.0.1:8010/api/health
# {"code":0,"message":"ok","data":{"status":"up",...}}
```

### 5.4 前端（开发模式编译监听）

```bash
cd student-app
npm install          # 第一次
npm run dev:app      # 一直开着，改代码自动重编
```

产物在 `student-app/dist/dev/app`。

## 6. 真机调试（核心流程）

### 6.1 手机准备

1. 用**数据线**连电脑（纯充电线不行，插上没反应就是线的问题）
2. 手机通知栏下拉 → USB 用途选 **「传输文件 / MTP」**
3. 开启开发者选项（连点「版本号」7 次）→ 打开 **「USB 调试」**
4. 手机弹出「允许 USB 调试吗」→ 勾「一律允许」→ 允许

### 6.2 确认设备认到了

adb 用 HBuilderX 自带的，不用另装：

```bash
"D:\hbuilderx\plugins\launcher-tools\tools\adbs\adb.exe" devices
```

（路径按自己 HBuilderX 安装位置调整）

看到 `xxxxx  device` 就对了。显示 `unauthorized` 说明第 4 步没点允许。

### 6.3 建立端口转发

```bash
"D:\hbuilderx\plugins\launcher-tools\tools\adbs\adb.exe" reverse tcp:8010 tcp:8010
```

验证手机侧能通（这一步最关键，通了后面基本不会卡）：

```bash
"D:\hbuilderx\plugins\launcher-tools\tools\adbs\adb.exe" shell "curl -s http://127.0.0.1:8010/api/health"
```

返回 `{"code":0,...}` 就说明手机已经能访问电脑上的后端了。

> **每次重新插数据线、或重启电脑、或重启 adb，转发都会失效。**
> 现象是 APP 里所有请求报网络错误，重跑一次 `adb reverse` 即可。

### 6.4 HBuilderX 运行到手机

1. HBuilderX → **文件 → 打开目录** → 选 `student-app\dist\dev\app`
   - ⚠️ 是 `dist\dev\app`，**不是** `dist\build\app`，也不是项目根目录
   - 打开错目录是最常见的坑：界面能开，但看到的是几天前的旧代码
2. 菜单 **运行 → 运行到手机或模拟器 → 运行到 Android App 基座**
3. 选设备 → 第一次会装「HBuilder 标准基座」APK，手机上点安装

### 6.5 改代码后的循环

```
改源码 → npm run dev:app 自动重编（约 12 秒）→ HBuilderX 重新点「运行到手机」
```

**必须重新点运行**，只刷新页面或切后台再回来，不一定加载新资源。

## 7. 日常协作流程

```
① git pull --rebase              拿到对方最新代码
② 改代码
③ 本地验证                       服务跑着，真机上看效果
④ git add <具体文件>             不要用 -A，避免把本地配置带上去
⑤ git commit -m "..."            写清楚改了什么、为什么
⑥ git pull --rebase              再同步一次，避免被拒
⑦ git push origin main
```

**提交前自查**：

```bash
git status --short
```

确认列表里**没有** `.env`、`node_modules`、`dist/`、`*.local`。
如果有，说明 `.gitignore` 漏了，先别提交。

**两人同时改同一个文件**时，后推的人会冲突。处理方式：

```bash
git pull --rebase
# 手工解决冲突文件
git add <冲突文件>
git rebase --continue
git push
```

## 8. 踩过的坑（照着避开）

| 现象 | 原因 | 解决 |
|---|---|---|
| APP 打开正常，所有请求报网络错误 | 后端没起 / adb 转发失效 | 查 `8010` 是否监听；重跑 `adb reverse` |
| 后端起不来，或手机请求返回 404 | HBuilderX 占了 8000 | 后端改 8010，转发也改 8010 |
| moto 启动报「以一种访问权限不允许的方式…」 | 9000 被占 | 换 9001，`.env` 同步改 |
| 改了按钮样式/文案，手机上没变化 | HBuilderX 打开的是 `dist/build/app` | 改成打开 `dist/dev/app`，并重新点运行 |
| 改了 `config/*.json` 不生效 | `read_json_config` 带 `@cache` | **重启后端** |
| 手机拍照上传失败、相册正常 | 相机路径 `uploadFile` 读不到 | 代码已用 `uni.saveFile` 兜底，勿回退 |
| 上传报「文件内容与扩展名不符」 | 文件名扩展名和真实内容不一致 | 检查上传时传的 `name` 是否从原路径推断 |
| 表格类文件数页数特别慢 | `.xls` 老格式要多转一次，宽表格还要多轮渲染 | 提示用户另存为 `.xlsx` |

## 9. 上手验证清单

按顺序做完，全绿就说明环境通了：

- [ ] `curl http://127.0.0.1:8010/api/health` 返回 `code:0`
- [ ] `adb devices` 显示 `device`
- [ ] `adb reverse tcp:8010 tcp:8010` 后再 `adb shell curl` 同一地址能返回
- [ ] HBuilderX 打开 `dist/dev/app`，运行到手机，APP 能进首页
- [ ] 首页能加载排队人数和公告（说明接口通了）
- [ ] 「文档转换」→ PDF 转 Word 能跑通（说明对象存储和转换链路正常）
- [ ] 下单页能选自己手机里的文件（说明系统选择器正常）
- [ ] 下单 → 支付 → 在「我的订单」看到（说明全链路通）

## 10. 两人协作的几个约定

1. **后端各自本地跑**，数据库各自本地。不要试图共用一套服务——
   除非做内网穿透，否则没有必要，而且互相改数据会互相干扰。
2. **`backend/.env` 各不相同**（端口、路径、口令），永远不要提交，也不要用对方的。
3. **提交粒度小一点**，一次 commit 讲清一件事。真出问题好回滚。
4. **改完先在真机点一遍再提交**。这个项目前端和后端耦合紧，
   只靠编译通过就提交，很容易把「按钮点了没反应」这类问题带上去。
5. 遇到「改了没生效」，先确认三件事：HBuilderX 打开的是 `dist/dev/app` 吗？
   重新点运行了吗？后端改配置后重启了吗？
